# Glide UX 변경 — 2026-09-12

상태: 구현 및 Windows 검증 진행 중. Production Ready 판정은 보류한다.

## 사용자 요구와 동작

- OS 제목 표시줄을 없애고 로고·앱 이름 / 빈 이동 영역 / 화면 설정 / 뒤로 / 앞으로 / 최소화 / 닫기 순서의 고정 헤더를 사용한다.
- 명령 버튼은 아이콘 오른쪽에 짧은 기능명을 표시한다. 설명 문장과 단축키는 툴팁에 유지한다. 높이 44 DIP, 곡률 22 DIP의 캡슐 버튼이며, 본문은 최소 폭 88 DIP, 상단은 최소 폭 76 DIP를 사용한다. 재생 버튼은 상태 변경에도 폭이 바뀌지 않는다.
- 홈의 설명 문구와 큰 카드를 제거한다. 녹화/발표 선택 캡슐의 표시기가 이동하며, 오른쪽에는 시작과 최근 녹화 버튼을 둔다. 최근 녹화는 독립 화면으로 열린다.
- 녹화와 발표는 같은 커서 카메라를 사용한다. 기본 1.5배, Ctrl+Shift+↑/↓로 0.1배씩 1.2–2.0배를 조절한다. Ctrl+Shift+F9는 전체 보기/확대 전환, F10은 추적 고정, F11은 화면 가림, F12는 종료다.
- 배율 전환은 현재 프레임에서 420ms로 이어지고 전환 도중 재입력해도 현재 배율에서 새 목표로 이어진다. 커서는 화면 가장자리를 넘지 않는 범위에서 중심의 좁은 안전 영역을 따라간다. 원본과 카메라 경로를 함께 저장한다.
- 입력 장치를 명시적으로 선택하고 소리 테스트를 시작하면 실제 WASAPI 장치의 피크 레벨을 표시한다. dB 눈금의 입력 레벨 미터이며 주파수 보정용 EQ는 아니다. 테스트는 파일을 쓰거나 마이크를 스피커로 재생하지 않는다. 이동/녹화 시작/종료 시 테스트를 해제한다.
- 편집 재생 바의 같은 트랙 위에 선택 시작/끝 핸들과 선택 구간을 겹친다. 별도 선택 줄 없이 선택 핸들과 재생 위치를 함께 확인한다. 핸들은 마우스 또는 방향키로 조절하고 숫자는 소수점 두 자리로 표시한다. 구간 변경 자체는 원본을 수정하지 않는다.
- 녹화의 별도 화면 캡처 버튼을 제거한다.
- 발표의 창 모드 보조 화면은 입력 창이 있는 모니터의 작업 영역 우하단에서 24px 떨어져 열린다. 작업 표시줄을 피하고, 처음 열린 뒤에는 자유롭게 이동할 수 있다. 별도 모니터 전체 화면 출력과 전체 모니터 입력의 반복 캡처 방지는 기존 동작을 유지한다.
- 세션 제어는 반투명 한 줄 아일랜드, 높이 64 DIP/곡률 32 DIP, 원형 버튼으로 구성한다. 이동 영역은 Thumb의 포인터 캡처로 동작하며 키보드 이동도 지원한다.

## 화면 전체 공유

전체 모니터를 입력으로 쓰면서 같은 화면에 공유용 출력 창을 표시하면 그 창이 입력으로 되돌아올 수 있다. 출력 창을 회의 앱이 캡처할 수 있도록 유지하면서 반복 캡처를 막기 위해, 창 공유 출력은 가상 데스크톱 바깥에 둔다. 별도 모니터 전체 화면 출력은 입력과 다른 모니터에서만 가능하다. 실제 회의 앱의 창 선택/최소화/전송 결과는 별도 검증 항목이다.

## 변경에 필요한 합격 기준

- 두 모드에서 선택 → 시작 → 배율 조절 → 일시정지/재개 → 종료 → 프로젝트 열기가 완료되고 예외/손실이 없어야 한다.
- 실제 Windows 마우스로 헤더/아일랜드/구간 핸들이 움직이며 버튼 클릭과 이동이 충돌하지 않아야 한다.
- 원본과 저장된 카메라 경로, 편집 미리보기/출력이 일치해야 한다.
- 마이크/시스템 장치 끔, 정상 신호, 무음, 장치 제거, 권한 거부를 구별해야 한다. 장치나 오류를 가짜 레벨로 숨기면 안 된다.
- 100/125/150/200% DPI, 좁은 창, 다중 모니터, 다크/라이트/고대비, 모션 감소, 키보드 접근성을 확인해야 한다.
- 기존 G00–G11, M01–M11 및 오디오/성능/배포 기준은 유지한다. 짧은 VM 검증을 실제 Windows 하드웨어 인증이나 회의 앱 호환성으로 대체하지 않는다.
