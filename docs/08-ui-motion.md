# UI 모션 구현과 검증

2026-09-12 · 유려한 제품 모션 · 개발 후보 · **NOT READY**

## 적용 범위

앱의 화면 전환과 조작 피드백에 적용합니다. 녹화 영상의 확대, 커서 평활화, 발표 카메라와 그 시간축은 변경하지 않습니다. 프로젝트 형식과 네이티브 미디어 ABI도 그대로입니다.

| 장면 | 구현 |
| --- | --- |
| 홈 카드 | 호버/키보드 포커스에서 3px 상승·1.01배, 누를 때 0.98배. 120~160ms |
| 모드 진입 | 같은 창의 카드 아이콘→준비 아이콘 연결. 제목·대상 카드·하단 행동을 32ms 간격으로 배치, 최대 320ms |

| 대상 미리보기 | 이전 소스를 즉시 비우고 새 실제 프레임이 준비되면 180ms·0.985→1배로 표시 |

| 컨트롤 바 | 창은 고정하고 내부 콘텐츠만 180ms 등장. 상태가 확정된 뒤 120ms 레이블 피드백과 활성 강조 |

| 저장 결과 | 실제 MP4/PNG 저장 또는 복사가 성공한 뒤 완료 패널·아이콘, 저장한 파일 열기 |

진입 곡선은 `(0.16, 1, 0.3, 1)`, 퇴장은 `(0.4, 0, 1, 1)`입니다. 레이아웃의 폭·높이·여백을 프레임마다 바꾸지 않고 XAML 합성 속성 Translation·Scale·Opacity를 사용합니다. 구간 탐색과 재생 헤드는 직접 입력을 그대로 반영합니다. 가리기·일시정지·종료·파일 저장을 애니메이션 완료까지 지연하지 않습니다.

## 설정과 수명

‘화면 설정’에서 테마와 UI 모션 표준/감소를 선택합니다. 기본은 표준이며 Windows에서 애니메이션을 끈 상태가 우선합니다. 감소 모드는 이동·확대·순차 지연을 없애고 최대 80ms 페이드만 사용합니다. 설정 변경 시 진행 중 효과를 정리합니다. `preferences.json`의 기존 테마와 알 수 없는 추가 설정을 보존하면서 `uiMotion` 값을 저장합니다.

`MotionPolicy`는 시스템 설정을 구독하고, 각 창의 `MotionCoordinator`는 실행 중 효과·버튼 이벤트를 소유합니다. 빠른 연속 전환은 이전 완료 콜백을 폐기합니다. 창을 숨기거나 종료하면 효과를 정리하며 사라지는 화면의 입력은 즉시 차단합니다. `CountdownRing`은 사용자 입력이나 캡처를 수집하지 않는 UI 전용 합성 도형입니다.

Windows 실행 중 발견한 두 문제를 수정했습니다. XAML 합성 속성을 쓰는 요소에서 `GetElementVisual`을 다시 호출하면 접근 오류가 발생해 스레드의 공통 컴포지터를 사용하도록 바꿨습니다. 합성기가 참조 중인 애니메이션·곡선 객체를 `IClosable.Close`로 먼저 닫으면 네이티브 종료가 발생해 강제 닫기를 제거하고 이벤트 해제·애니메이션 중단 후 COM 참조 수명에 맡깁니다. 실패 결과와 Windows 오류 기록은 별도로 보존합니다.

## 재현 명령

잠금 해제된 Parallels Windows PowerShell에서 `scripts/Verify-UI-Motion.cmd`를 실행합니다. 실제 WinUI publish → 설정 호환성 검사 → 실제 합성기 검사 순서입니다. `scripts/Launch-Motion-Gallery.cmd`는 개발용 조작 화면을 엽니다. 두 진입점은 개발 진단 환경에서만 활성화되며 사용자 설정이나 영상 프로젝트를 변경하지 않습니다.

`scripts/Launch-UI-Test.cmd`로 두 모드를 수동 검사합니다. 테스트 창은 180초 뒤 종료하므로 이를 앱 충돌이나 수동 녹화 종료로 기록하지 않습니다. `scripts/Collect-Motion-Evidence.cmd`는 앱 진단·설정·바이너리 해시만 수집합니다.
