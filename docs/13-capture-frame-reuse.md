# 중복 프레임 읽기 제거와 시간축 검증

## 이번 변경

녹화의 `RecordingSink`가 같은 원본 프레임을 다시 저장할 때 GPU 읽기와 CPU 픽셀 복사를 반복하지 않도록 수정했습니다. 성공적으로 읽은 픽셀을 원본 프레임 번호와 세션 epoch로 식별합니다. 크기 검사, 일시정지·종료 후 진행 중 프레임 폐기, 커서·발표 구도의 시간별 기록은 계속 수행합니다. 바뀐 원본과 새 세션은 다시 읽습니다.

성능 보고서 버전 2의 `readback.count`는 실제 읽기를 시도해 완료한 횟수이며 `pixelCacheHits`는 재사용하여 저장한 프레임 수입니다. 초기 준비 읽기는 이 횟수에서 제외됩니다. 일시정지 직전에 완료했지만 저장하지 않은 읽기가 있을 수 있어 두 수의 합이 항상 저장 프레임 수와 같지는 않습니다.

개발용 프레임 기록에는 WGC 원본 시각, 원본 획득·게시, 픽셀 읽기 시작·완료, 인코딩 시작·완료의 QPC와 녹화 원점·누적 일시정지 시간을 추가했습니다. WGC 시각이 직접 읽은 QPC보다 앞서는 음수 나이도 원본 기록에 그대로 남깁니다. 이 값들을 실제 GPU 실행 시간이나 물리 디스플레이 지연으로 해석하지 않습니다.

`Inspect-CaptureTiming.py`는 MP4를 FFmpeg로 디코딩한 프레임 번호를 네이티브 기록과 연결합니다. 같은 원본 키가 다른 화면으로 바뀌지 않는지, 캐시 사용 때 읽기 시간이 0인지, 기록 시각과 저장 시간축이 맞는지 확인합니다. 강제 종료로 마지막 진단 행이 잘렸다면 위치와 바이트 수를 명시하고, 확정된 영상의 모든 프레임에 완전한 기록이 있는지 별도로 검사합니다. 중간 손상·줄바꿈으로 끝난 잘못된 JSON·확정 프레임 누락은 허용하지 않습니다. 이 진단 검사는 기존 영상 품질 게이트를 대체하지 않습니다.

같은 앱에서 테스트 창을 선택하고 마이크·시스템 소리를 끈 뒤 녹화를 시작했습니다. 도구 모음에서 일시정지·재개·종료를 수행했고, 편집기 진입과 재생 진행을 확인했습니다.

- 일시정지 **23.7278초**가 프로젝트 시간축에서 제거됐습니다. 정지 전후 저장 프레임은 538→539이며 간격은 33.33ms입니다. 재개 직후 원본 번호는 546→1323으로 바뀌었고 픽셀을 새로 읽었습니다.
