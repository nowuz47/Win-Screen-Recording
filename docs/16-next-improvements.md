# 개선 계획 — 2026-09-26

기준 후보는 `app-x64-build-23403-439`다. 네이티브 검사와 발표 회귀 6/6, WinUI 빌드, 버튼 레이블·발표 우하단 배치·편집 바의 겹침과 클릭 탐색을 확인했다. 긴 드래그와 손잡이 키보드 포커스는 미확인이다. 아래 작업은 기존 G00–G11 / M01–M11 출시 기준을 대체하지 않는다.

## 1차: 입력 신뢰성과 검증 가시성 — 구현 중

- 재생 바의 선택 손잡이는 움직이지 않는 트랙 기준으로 포인터 이벤트 좌표를 읽는다. 지연된 이벤트를 처리할 때 전역 커서의 최신 좌표를 다시 조회하지 않는다.
- 창과 아일랜드 이동도 이벤트 좌표와 현재 창 위치·DPI로 처리한다. 오른쪽 버튼과 다른 포인터가 활성 드래그를 가로채지 않게 하고, 해제 시 마지막 좌표를 반영한다.
- 손잡이를 누르면 해당 컨트롤에 포커스를 준다. 좌우 방향키는 0.01초, Home/End는 유효 구간 끝으로 이동한다. 접근성 이름에 현재 선택값을 포함한다.
- Escape, 캡처 상실, 포인터 취소, 컨트롤 제거 시 드래그 상태를 해제한다. 편집 트랙 크기 변경 중에는 드래그를 취소한다. 선택 변경은 삭제·유지 명령 전까지 원본을 수정하지 않는다.
- Windows 검사 시작/단계/종료 코드를 공유 폴더에 즉시 기록한다. 실패한 단계는 다음 단계로 넘어가지 않는다. 과거 로그를 새 검사 결과로 오인하지 않도록 실행별 로그를 남긴다.

합격 기준: 좌우 긴 드래그와 되돌리기에서 손잡이가 포인터를 따르고 경계 밖 값이 생기지 않는다. 클릭 후 방향키가 재생 위치나 창 대신 해당 손잡이를 조절한다. 취소 후 새 드래그가 가능하며 바 사이 클릭 탐색은 유지된다. 창과 아일랜드 모두 이동하고 버튼 클릭과 충돌하지 않는다. 실제 Windows 빌드와 새 후보의 UI 관찰을 연결한다. 도구 입력만으로 판단할 수 없는 항목은 미확인으로 남긴다.

## 2차: 작은 화면과 접근성

- 100/125/150/200% DPI와 좁은 창에서 헤더, 편집 패널, 아일랜드를 점검한다.
- 아일랜드의 한 줄 형태와 종료 버튼 접근성을 유지하면서 숨은 보조 명령의 발견·키보드 접근을 개선한다. 필요한 경우 명시적 더보기 메뉴를 사용한다.
- Tab 순서·포커스 표시·고대비·모션 감소를 점검하고 상태별 레이블이 버튼 크기를 바꾸지 않게 한다.

합격 기준: 주요 명령이 잘리지 않고 키보드로 도달 가능하며, 작업 영역·배율 변경 후 종료 수단이 화면 안에 남는다. 모션 감소에서도 현재 모드와 녹화 상태가 명확하다.

## 3차: 실제 사용과 출시 검증

- 새 후보에서 녹화 → 일시정지/재개 → 편집 → MP4 저장 → 다시 열기를 검증한다.
- 실제 마이크 발화, 시스템 소리, 장치 분리·권한 오류, 실제 회의 앱 창 공유를 검증한다.
- 실물 Windows 장비의 장시간 녹화·프레임 손실·A/V 동기화·복구, 설치·서명·배포 기준을 순서대로 충족한다.
