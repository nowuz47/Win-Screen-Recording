# 두 모드 UI·UX와 구현 현황

2026-09-12 · **개발 후보 / Windows 기능·주요 UI 흐름 확인 / 영상 품질 FAIL / NOT READY**

이 문서는 녹화 모드와 프레젠테이션 모드를 분리하는 합의안을 코드와 검증 항목으로 연결합니다. [Screen Studio](https://screen.studio/)의 화면 중심 편집 방향과 이전 커서 모션 시안을 참고했습니다. 아래 성능 수치는 Glide의 목표이며 참고 제품의 측정 결과가 아닙니다.

## 사용자 흐름

후속 UI 모션은 [UI 모션 구현과 검증](08-ui-motion.md)에 정의했습니다. 아래 표의 모션은 영상·발표 카메라의 동작이며, 앱 화면 전환과 설정은 별도로 관리합니다. 최종 UI 빌드의 검사·관찰 범위는 후속 문서의 증거를 적용합니다.

| 항목 | 녹화 모드 | 프레젠테이션 모드 |
| --- | --- | --- |
| 사용 목적 | 설명 영상을 만들어 나중에 전달 | 현재 조작 중인 화면을 청중에게 설명 |
| 진입 | 홈 → 녹화하기 | 홈 → 프레젠테이션 |
| 준비 | 대상 선택·미리보기 → 카운트다운 | 입력 창·출력 위치·배율 → 가려진 발표 창 준비 |
| 확대 | 녹화 후 자동 분석, 수동 수정 | 사용자가 확대를 켜고 커서 위치를 자동 추적 |
| 모션 | 기본 650ms 전환, 250ms 미리 보기 분석 | 미래 입력을 쓰지 않는 250ms 전환, 기본 1.6배 |
| 진행 중 제어 | 녹화 일시정지·종료 | 확대·고정·가리기·발표 종료와 별도의 녹화 제어 |
| 저장 | 원본·커서 → 프로젝트 → 편집 → MP4 | 기본은 저장 없음. 명시적으로 녹화하면 원본·커서·발표 구도 저장 |
| 종료 | 자동 저장 후 편집기 | 출력 중단. 녹화했다면 저장된 프로젝트를 편집기로 연결 |

발표는 별도 `Glide Presentation` 창에 출력합니다. 원본 앱의 화면, 배율, 입력 좌표를 변경하지 않습니다. 회의 앱에서 이 창을 공유하거나 확장 모니터에 출력합니다. 현재 창 공유는 사용자가 회의 앱에서 선택하며, 회의 앱의 음성 공유도 그 앱에서 설정합니다.

단일 모니터 발표의 입력은 창입니다. 전체 모니터 입력은 출력과 다른 확장 모니터가 필요합니다. 동일 모니터·겹치는 모니터·앱 자신의 출력 창 입력을 거부합니다. 영역 선택은 후속 구현입니다. 대상 선택을 바꾸려면 현재 후보에서는 발표를 종료하고 다시 준비합니다. 가림 상태에서 안전하게 대상을 교체하는 흐름은 별도 작업입니다.

## 화면과 조작 규칙

- 홈: 두 모드를 동등하게 배치하고 최근 녹화를 아래에 둡니다. 준비 화면은 선택한 대상의 미리보기와 시작 행동에 집중합니다.
- 다크 테마를 기본으로 하고 민트색을 주 행동에 사용합니다. 라이트·시스템 테마와 Windows 고대비 리소스를 제공합니다. 테마 선택은 사용자 설정에 저장합니다.
- 진행 중에는 독립된 항상 위 컨트롤 바를 사용합니다. 컨트롤 바의 캡처 제외를 요청하고, 실패하면 명시적으로 알립니다. 청중 출력 창에는 컨트롤 바를 넣지 않습니다.
- 발표 단축키: `Ctrl+Shift+F9` 확대, `F10` 위치 고정, `F11` 화면 가리기, `F12` 발표 종료. 네 키 모두 Ctrl+Shift와 함께 누릅니다. 발표 준비 중에 등록하고 종료 시 해제합니다. 충돌하면 버튼을 유지하고 안내합니다.
- `Ctrl+Shift+R`은 녹화 종료입니다. 발표 중 사용해도 발표 세션은 유지합니다.
- 가리기는 중립 화면으로 전환하고 원본 수집을 중단하며 선택적 녹화를 일시정지합니다. 다시 보여줄 때 새 프레임이 준비된 뒤 녹화 시간을 재개합니다. 사용자가 직접 누른 녹화 일시정지는 해제하지 않습니다.
- 녹화 30분 상한은 녹화에만 적용합니다. 발표는 계속됩니다. 상한 사전 안내와 30분 실제 재현은 추가 구현·검증 대상입니다.
- 편집기는 하나의 탐색 위치와 재생 화면을 사용합니다. 확대 블록은 남겨진 영상 시간에 맞춰 표시하며, 선택하면 속성을 엽니다. 시작·끝 구간 값과 슬라이더, 삭제·유지, 실행 취소·다시 실행, 확대 잠금·재분석을 제공합니다.
- 선택한 확대의 초점은 미리보기를 클릭해 옮깁니다. 드래그 핸들·썸네일 타임라인·키보드 편집 단축키와 작은 창의 검사 패널 접기는 후속 구현입니다.
- 영상 비율 16:9·1:1·9:16, 배경·여백·모서리·커서 크기·평활화·표시·클릭 강조를 프로젝트에 저장합니다. MP4는 사용자가 선택한 폴더에 충돌 없는 새 이름으로 저장합니다.
- PNG는 선택 대상의 실제 프레임을 확인한 뒤 저장 또는 복사합니다. 편집 스타일을 적용한 PNG는 아직 제공하지 않습니다.

## 코드 경계

| 구성 | 책임 | 관련 소스 |
| --- | --- | --- |
| 모드·세션 | 발표 상태와 녹화 상태의 독립성 | `Glide.Core/PresentationSession.cs`, `Glide.App/MainWindow.Modes.cs` |
| 화면 수집 | WGC GPU 프레임 소유권·수집 세대·대상 수명 | `capture_source.inl` |
| 녹화 소비자 | 선택적으로 파일 생성·단일 시간축·일시정지·세그먼트 확정 | `recording_sink.inl` |
| 청중 출력 | 별도 Win32 창·SwapChain·중립 화면·실시간 구도 | `presentation_pipeline.inl` |
| 합성 | 배경·잘라내기·커서·클릭·둥근 모서리 | `gpu_compositor.inl` |
| 미리보기·내보내기 | 유지되는 디코더와 공통 GPU 합성 경로 | `preview_pipeline.inl`, `Glide.Media/MediaRenderer.cs` |
| 프로젝트 v2 | 스타일·비율·발표 구도 사용 여부, v1 원본 백업 | `Glide.Core/ProjectStore.cs`, `CaptureImport.cs`, `RenderPlan.cs` |

발표 카메라는 현재/과거 입력만 사용하고, 화면으로 보낸 구도를 녹화 시간에 기록합니다. 편집 재생에서는 이 구도를 시간으로 조회하므로 탐색 순서가 결과를 바꾸지 않습니다. 잠긴 수동 확대는 발표 구도를 해당 구간에서 덮어쓰며, 전체 확대 해제와 자동 재분석은 기록된 구도 사용을 끕니다.

렌더 ABI는 v2이며 새 앱은 구형 렌더 DLL을 거부합니다. Capture ABI v1은 유지하고 별도의 Live ABI v1을 추가했습니다. DLL을 새 앱과 함께 배포해야 합니다. 원본 파일과 확정 저널은 기존 저장·복구 경계를 유지합니다. 저장 없는 발표는 녹화 소비자를 만들지 않습니다.

## Windows 검증 재개

잠금이 해제된 Parallels Windows PowerShell에서:

```powershell
& '\\Mac\Home\Desktop\AI Slops\Win-Screen-Recording\scripts\Verify-Modes.cmd'
```

네이티브 `/W4 /WX` 빌드 → 코어 → 기존 캡처·복구 → 기존 렌더 → 발표 4개 통합 검사 → WinUI publish 순서입니다. 빌드 매니페스트는 모든 `.inl` 파일을 포함합니다. 로그·원본 테스트 미디어·결과는 `.artifacts`의 실행별 폴더에 보존합니다.

발표 검사는 별도 프로세스가 만든 테스트 창만 입력으로 사용합니다. 준비 중 수집 없음, 실제 청중 창 픽셀, 가림 후 중립 출력, 저장 없는 세션, 명시적 녹화의 일시정지, 녹화 종료 후 발표 지속, 녹화된 카메라 구도, 재귀 입력·NaN 거부와 가림·복귀·폐기 5회 반복을 검사합니다. 마이크·사용자 데스크톱·회의 상대를 자동으로 녹음하거나 공유하지 않습니다.

같은 후보의 주요 UI 흐름은 위 결과에 기록했습니다. `scripts/Build-And-Launch-UI-Test.cmd`는 앱을 빌드하고 180초 후 자동 종료하는 테스트 창과 앱을 엽니다. CUA가 텍스트를 전달한 직후에는 입력이 끝나지 않을 수 있으므로 파일명 전체 표시를 확인하고 저장하며, 숫자 편집은 Enter로 확정합니다. 테스트 창의 자동 종료를 수동 녹화 종료나 앱 충돌로 기록하지 않습니다.

추가 검증은 Zoom/Teams 창 선택과 실제 수신 화면, 확장 출력·혼합 DPI, 대상 최소화·출력 모니터 분리·GPU 손실·앱 종료·잠금 복구를 포함합니다. 장비별 반복 수와 성능·접근성 증거가 없으면 모드별 출시 게이트를 통과로 바꾸지 않습니다.

## 남은 출시 차단 항목

먼저 250ms 이상 프레임 간격과 발표 녹화의 빈 색상 패치 프레임을 재현하고 원본 그리기·WGC 수집·GPU 읽기·인코더 시간을 분리해 원인을 좁혀야 합니다. 같은 원시 실패 표본을 보존하고 수정된 DLL로 독립 디코더 검사를 다시 통과시킵니다.

WASAPI 마이크·시스템 오디오, 독립 입력 수집, 영역 선택, 안전한 발표 대상 교체, 완성된 편집 타임라인, 접근성 실측, 공유 서비스와 접근 제어, 서명된 설치·업데이트, 장비별 성능·장시간·14일 베타도 남아 있습니다. 기존 G00~G11과 [모드별 추가 조건](07-two-mode-release-gates.md)을 모두 충족해야 Production Ready입니다. 이번 후보는 기반 구현이며 정식 출시물이 아닙니다.
