# 출시 후보 판정표

관련 기준: [Production Ready v1.0](04-production-readiness.md)

두 모드 후보는 [M01~M11 추가 판정표](07-two-mode-release-gates.md)의 모든 항목에도 같은 상태·실측·증거·담당자·차단 사유를 기록해야 합니다. 모드 기준 누락은 출시 보류입니다.

이 파일은 증거를 모아 판정할 때 사용하는 양식입니다. 현재 어떤 항목도 통과한 것으로 채우지 않았습니다. 실제 릴리스마다 복사해 해당 후보의 기록으로 보존합니다.

| 기본 정보 | 기록 |
| --- | --- |
| 기준 버전 | Production Ready v1.0 |
| 후보 버전·소스 revision | 미정 |
| 앱·엔진 바이너리 해시 | 없음 |
| 서명된 배포물 해시·검증 결과 | 없음 |

## 시나리오별 증거 양식

| 항목 | 기록할 내용 |
| --- | --- |
| 요구사항·시나리오 ID | 제품 요구사항 ID와 Gxx 세부 기준 |
| 환경 | OS 빌드, CPU/GPU/드라이버, RAM/SSD, DPI, 앱 버전, 전원·네트워크 조건 |
| 입력 | 프로젝트·기준 영상·이벤트 데이터·해시, 테스트 시드 |
| 기대 결과 | 실행 전에 고정한 임계값·허용 오차 |
| 관측 결과 | 성공/실패 건수, p50/p95/최대, 신뢰구간 등 해당 수치 |
| 예외 | 취소·제외 시도와 이유. 실패·재시도도 보존 |
| 증거 | 원시 로그·미디어·측정 스크립트·스크린샷·서명 결과 경로 |
| 판정 | 상태, 실행자, 검토자, 날짜 |

## 결함과 범위 변경

등록된 결함 수가 없다는 것은 테스트 완료나 무결함을 뜻하지 않습니다. 발견한 결함마다 등급, 재현 절차, 사용자 영향, 수정 revision, 재검증 증거를 기록합니다. P2 수용은 필수 기준을 위반하지 않는 경우에만 허용합니다.

범위 변경은 이전 범위, 변경 이유, 사용자 안내 변경, 영향을 받는 게이트, 결정 책임자·날짜를 기록합니다. 실패 데이터를 삭제하거나 수정 전 결과를 현재 후보의 성공으로 바꾸지 않습니다.

## 최종 확인

- [ ] G00~G11 모두 PASS이며 모든 결과에 증거가 연결되어 있다.
- [ ] P0·P1 미해결 0건이며 원인 미확인 데이터 손실이 없다.
- [ ] 수용하는 P2마다 영향·우회법·담당자·수정 목표 버전이 있다.
- [ ] 테스트한 바이너리와 배포할 바이너리가 일치한다.
- [ ] 프로젝트 이관·배포 중단·정상 버전 복원·공유 삭제 복원 방지가 검증되었다.
- [ ] 출시 책임자와 검토자가 판정했으며 운영 담당자에게 인계했다.

현재 결론: **NOT READY. 구현과 검증이 시작되지 않았습니다.**
