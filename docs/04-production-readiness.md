# Production Ready 기준 v1.0

기준 수립일: 2026-09-10 · 적용 대상: 첫 정식 출시(GA)와 이후 정식 업데이트

**Production Ready는 명시한 지원 환경에서 사용자가 녹화·편집·저장·공유를 완료할 수 있고, 실패 시 데이터를 보호하며, 배포 후 장애를 발견하고 대응할 수 있음을 검증한 상태입니다.**

이 문서의 수치는 이 제품을 위해 정한 출시 판정 기준입니다. 업계 공통 인증이나 현재 달성한 성능을 의미하지 않습니다. 현재 개발을 시작했고 일부 코어 검증을 수행했지만 필수 출시 게이트를 통과하지 않았으므로 **Production Ready가 아닙니다.** 실제 진행 상황은 [개발 현황](05-development-status.md)에 기록합니다.

## 판정 원칙

2026-09-11부터 녹화·프레젠테이션 두 모드를 포함하며 [모드별 추가 필수 기준 M01~M11](07-two-mode-release-gates.md)을 함께 적용합니다. 아래 G00~G11은 유지합니다. 새 발표 코드가 추가된 것만으로 기존 Windows 검증을 새 후보에 승계하지 않습니다.

- 아래 G00~G11을 모두 `PASS`로 판정하고, 출시를 차단하는 결함이 없어야 정식 출시합니다.
- 필수 기준의 실패, 표본 부족, 증거 누락, 측정 환경 미기재는 출시 보류입니다. 평균 점수로 상쇄하지 않습니다.
- `N/A`는 확정된 출시 범위 밖의 세부 항목에만 사유를 붙여 사용합니다. 첫 출시 범위인 캡처·녹화·편집·저장·공유는 제외할 수 없습니다.
- Beta와 GA를 구분합니다. 기존 개발 계획의 공개 베타 도달만으로 Production Ready라고 부르지 않습니다.
- 성능을 검증할 장비와 기준을 측정 전에 고정합니다. 실패한 뒤 불리한 장비·결과를 보고서에서 빼지 않습니다.
- 기능·지원 범위를 변경해야 하면 제품 문서와 사용자 안내를 먼저 갱신하고 새 범위에 대해 다시 판정합니다. 기록 없이 기준을 낮추지 않습니다.
- 모든 기준에는 담당 역할, 실제 담당자, 검토자, 대상 빌드, 테스트 날짜, 결과와 증거를 연결합니다. 작은 팀에서는 역할을 겸할 수 있지만 미디어·복구·접근 제어는 작성자 외 검토를 받습니다.

## G00 — 검증 대상 고정

첫 정식 버전의 기준 작업은 **단일 화면·창·단일 모니터 내 영역, SDR, 최대 30분 녹화, 마이크와 시스템 소리 2트랙, 기본 스타일·커서·확대 적용, 1080p 출력**으로 정합니다. 30분은 검증 상한입니다. UI에 이를 표시하고 상한 전에 알린 뒤 자동으로 안전 종료합니다. 더 긴 녹화를 지원하려면 상한과 장시간 시험을 함께 확대합니다.

모든 지원 장비는 1080p30을 충족해야 합니다. 1080p60은 아래 성능 기준을 통과한 장비군에서 제공하며, 앱은 녹화 전에 지원·설정 상태를 표시합니다. 60fps 실패를 숨기고 30fps로 저장하면서 60fps로 표시하지 않습니다.

Windows 11 x64 중 정식 출시 시점에 지원할 정확한 OS 빌드와 업데이트 번호를 명시합니다. 최소 RAM·GPU 기능·저장장치·필요 여유 공간도 실측 후 지원 표에 기록해야 합니다. 이 표가 비어 있으면 G00 실패입니다.

실기기는 최소 다음 네 구성을 포함합니다. 같은 장비를 이름만 달리해 중복 계산하지 않습니다.

| 장비군 | 대표 구성 | 필수 조합 |
| --- | --- | --- |
| H1 | 최소 사양 경계의 Intel 내장 GPU 노트북 | 배터리·전원 연결, 기본 1080p30 |
| H2 | AMD 내장 GPU 장비 | 1080p30, 지원 시 60fps |
| H3 | NVIDIA 외장 GPU와 내장 GPU가 있는 하이브리드 장비 | 캡처·인코더 GPU 조합, 1080p60 인증 후보 |
| H4 | AMD 외장 GPU 데스크톱 | 1080p60 인증 후보, 다중 모니터 |

각 장비에 CPU·GPU·RAM·드라이버·OS·전원 모드를 기록합니다. 캡처는 실기기에서 검증하고, 설치·권한·서버 테스트에는 VM도 사용합니다. 장비가 부족하면 호환성을 검증했다고 간주하지 않습니다.

디스플레이 조합은 100%·125%·150%·200% 배율, 혼합 DPI, 음수 화면 좌표, 세로 모니터, 창 이동·리사이즈를 포함합니다. 전체 조합의 무작정 곱 대신 각 값과 주요 쌍을 커버하는 테스트 표를 고정하고, 혼합 DPI + 창 이동 + 클릭 정합은 반드시 함께 시험합니다.

Windows 10·ARM64·HDR·보안 데스크톱·보호 콘텐츠·원격 세션·게임 전용 전체화면·여러 모니터에 걸친 영역은 첫 정식 지원 범위 밖으로 문서화합니다. 감지 가능한 미지원 조건은 시작 전에 안내합니다. 단순한 정지 화면만으로 보호 콘텐츠나 캡처 실패를 확정하지 않습니다.

## G01 — 기능 완료의 정의

[제품 기획](01-product-and-ux.md)의 ‘공개 첫 버전’ 기능마다 요구사항 ID와 테스트 ID를 연결합니다. 각 기능은 정상 완료뿐 아니라 취소·오류·다시 시도·다시 열기가 통과해야 완료입니다.

필수 종단 시나리오는 다음과 같습니다.

1. 새 설치 → 계정 없이 화면·창·영역 녹화 → 종료 → 자동 확대 미리보기 → MP4 저장.
2. 마이크·시스템 소리 각각 끔/켬, 동시 녹음, 권한 거부·장치 없음·장치 변경 처리.
3. 일시정지·재개 → 시작·끝 트림 → 중간 구간 삭제 → 실행 취소·다시 실행 → 저장·다시 열기.
4. 커서 크기·평활화·클릭 강조, 자동 확대 수정·삭제·잠금, 배경·여백·화면 비율 변경.
5. 화면 캡처 → PNG 저장·이미지 복사 → 외부 앱에 붙여넣기.
6. MP4 저장과 별도로 링크 공유 → 다른 기기에서 재생 → 링크 삭제·만료 확인.
7. 녹화·내보내기·업로드 중 취소 또는 실패 → 리소스 해제 → 같은 앱에서 재시도.
8. 한글·공백·이모지가 포함된 프로젝트명·저장 경로, 읽기 전용 경로·기존 파일 충돌 처리.

위 시나리오와 G00의 필수 조합은 **100% 통과**해야 합니다. 버튼 클릭이나 HTTP 성공 응답만으로 통과시키지 않고 생성된 파일·프로젝트·링크의 실제 내용을 검증합니다. 전역 단축키 등록 실패 시 대체 종료 수단을 제공하고 충돌을 알려야 합니다.

## G02 — 안정성과 표본

출시 후보(RC)의 동일한 앱·엔진 바이너리로 아래 조건을 충족합니다. 서명·배포 메타데이터만 달라지면 해당 차이를 남기고 실제 배포물에서 설치·실행 검증을 다시 합니다.

| 시험 | 최소 표본 | 통과 기준 |
| --- | --- | --- |
| 정상 녹화 수명주기 | 자동화 1,000회, H1~H4 각 200회 이상 | 전체와 각 장비군 녹화 완료율 ≥99.5%, 손상·미확인 데이터 손실 0건 |
| 내보내기 | 서로 다른 구간·효과 조합 1,000회, 각 장비군 200회 이상 | 전체와 각 장비군 유효 출력 성공률 ≥99.5% |
| 장시간 녹화 | 각 장비 30분 × 3회 | 12회 모두 정상 종료·전체 재생·동기화 기준 통과 |
| 반복 실행 | 각 장비 100회 시작·종료, G02의 1,000회에 포함 가능 | 장치 핸들·파일 잠금 누적 없음, 메모리 회수 기준 통과 |
| 베타 관찰 | 최소 14일, 동의한 사용자 10명 이상, 유효 녹화 200회 이상 | 충돌 없는 녹화 비율 ≥99%, 재현 가능한 P0·P1 미해결 0건 |

녹화 완료율의 분모는 준비 완료 후 사용자가 시작한 녹화 시도입니다. 분자는 종료 후 프로젝트를 다시 열고 원본·선택한 오디오·이벤트 시간 범위를 검증한 시도입니다. 앱 충돌·저장 실패를 분모에서 빼지 않습니다. 준비 전 권한 거부와 사용자가 의도적으로 버린 녹화는 별도 집계합니다.

내보내기는 사용자가 시작한 작업을 분모로, 완성 파일의 전체 디코딩·길이·트랙 검증을 통과한 작업을 분자로 삼습니다. 사용자 취소는 별도 집계하고 자동 재시도는 새 성공 표본을 늘리는 데 사용하지 않습니다. 최초 실패와 최종 복구 결과를 둘 다 보고합니다.

고의 장애 주입은 위 정상 성공률에 섞지 않고 G03에서 판정합니다. 수집에 동의하지 않은 사용자의 세션은 측정하지 않으며, 측정된 세션에 한정한 비율임을 표시합니다. 완료 로그가 없는 시작 기록을 자동 성공으로 간주하지 않고 조사합니다.

표본 수·실패 수·측정 기간·95% 신뢰구간을 함께 남깁니다. 관측 성공률은 미래의 무고장을 보장하지 않습니다. 99.5%를 넘더라도 필수 기능의 재현 가능한 실패나 원인 미확인 데이터 손실이 있으면 정식 출시하지 않습니다.

## G03 — 데이터 손실과 복구

‘확정 데이터’는 미디어 세그먼트 파일·저널·필수 이벤트가 디스크에 기록되어 복구 가능한 상태임을 확인한 범위입니다. 저장 완료 표시도 이 범위와 일치해야 합니다. 버퍼에만 들어간 데이터를 저장 완료로 표시하지 않습니다.

- 정상 종료 후 영상·오디오·이벤트·편집 revision의 손실은 0건이어야 합니다.
- 앱 프로세스 강제 종료 시 확정 데이터는 모두 복구하고, 녹화 꼬리 손실은 각 시험에서 **최대 10초** 이내여야 합니다. 5초 세그먼트 설계가 자동으로 이 기준을 만족한다고 가정하지 않습니다.
- 저장 완료를 표시한 편집은 다시 열었을 때 그대로 복구합니다. 편집 자동 저장은 마지막 조작 후 2초 이내 확정하는 것을 기준으로 하며, 실패하면 ‘저장되지 않음’을 표시합니다.
- 디스크 부족·쓰기 실패·대상 종료·장치 분리·GPU 장치 손실은 원본을 덮어쓰지 않고 가능한 범위를 확정합니다. 녹화 중단 이유와 복구 범위를 사용자에게 표시합니다.
- 전원 단절·저장장치 고장은 별도 시험으로 손실 범위를 측정합니다. 앱의 10초 꼬리 손실 기준을 물리적인 장치 고장 전체에 대한 보장으로 확대하지 않습니다. 부분 손상을 검출하고 살아 있는 확정 세그먼트를 보존해야 합니다.
- 복구 과정 자체가 중단되어도 재실행할 수 있어야 합니다. 내보내기 취소·파일 이름 충돌·정리 작업이 원본을 지워서는 안 됩니다.

장애 주입은 강제 종료, 저장 공간 소진, 접근 거부·쓰기 실패, 현재 세그먼트 손상, 장치 분리, 저장·복구 중 재종료를 포함해 **최소 60회**, 각 장애 유형 5회 이상, 각 장비군 10회 이상 실시합니다. 확정 세그먼트의 해시·길이·이벤트 범위를 장애 전후 비교하고 해당 복구 기준을 **100% 통과**해야 합니다.

## G04 — 영상·음성·커서 정확도

| 항목 | 정식 출시 기준 | 측정 방법 |
| --- | --- | --- |
| A/V 동기화 | 30분의 시작·매 5분·끝에서 절대 오차 ≤50ms | 공통 기준 신호를 가진 테스트 앱으로 입력 기준과 출력 비교 |
| 클릭 시간 | 기록된 클릭 기준 대비 강조 시점 오차 ≤출력 1프레임 | 60fps는 약 16.7ms, 30fps는 약 33.3ms. 대상 앱 자체 반응 지연은 분리 |
| 클릭 위치 | 핫스팟 오차 ≤원본 물리 좌표 2px | 각 DPI·창 경계·이동 조합에서 클릭 100회 이상. 원본 좌표로 역변환해 비교 |
| 화면·커서 합성 | 이중 커서·잘못된 핫스팟·유효하지 않은 가장자리 커서 0건 | 표준 포인터·텍스트·리사이즈·드래그 및 수동 처리 대상 검사 |
| 앱으로 인한 프레임 손실 | 각 지원 프로필의 30분 동적 테스트에서 <0.5% | 입력 기준 프레임 ID로 비교. 정적 화면 무갱신·의도적 fps 변환과 구분 |
| 영상 정지 | 동적 기준 영상에서 앱이 만든 연속 정지 <250ms | 프레임 ID와 타임스탬프 검증 |

| 미리보기·출력 일치 | 같은 시각의 초점·크롭·커서 오차 ≤출력 1px, 이벤트 ≤1프레임 | 인코딩 전 합성 기준 비교. 압축 영상의 픽셀 완전 일치는 요구하지 않음 |
| 파일 호환성 | 필수 출력 샘플 모두 끝까지 재생·임의 위치 탐색 가능 | Windows Media Player·Edge·Chrome의 테스트 당시 버전 기록 |

가로·정사각·세로, 마이크만·시스템 소리만·혼합·무음, 30/60fps의 지원 조합을 검사합니다. SDR 기준 패턴에서 심한 색 틀어짐·회색 검정·글자 가장자리 손상이 없어야 하며 색 공간·범위 메타데이터도 검사합니다.

원본 해상도보다 무리하게 확대할 경우 품질 손실을 숨기지 않습니다. 알 수 없는 커서나 원본에 그려진 소프트웨어 포인터는 지원 여부를 표시하고 해당 효과를 안전하게 제한합니다.

## G05 — 자동 확대와 체감 성능

모션 회귀 샘플은 클릭·더블클릭·머무름·긴 이동·스크롤·드래그·텍스트 선택·화면 가장자리·구간 삭제 경계를 포함해 **최소 30개**, 각각 가로·세로 출력으로 고정합니다. 모든 필수 샘플에서 다음을 만족해야 합니다.

- 확대 중 캡처 범위 밖의 빈 영역이 노출되지 않고, 강조한 클릭 대상이 출력 안에 유지됩니다.
- 커서가 안전 영역 안에 머무는 구간에서는 불필요한 카메라 왕복이 발생하지 않습니다.
- 클릭 고정점이 평활화 때문에 이동하지 않고, 드래그 의미가 바뀌지 않습니다.
- 기본 프리셋은 확대·축소 전환 450~800ms를 유지합니다. 짧은 구간은 전환을 겹쳐 흔들지 않고 효과를 축소·병합·생략합니다.
- 자동 재분석 후 잠근 수동 확대는 유지됩니다. 스크럽 순서와 재생 프레임률이 바뀌어도 같은 출력 시간의 구도가 같습니다.
- OS 애니메이션 감소 설정에 맞춰 UI가 바뀌고, 별도의 영상 ‘움직임 적게’ 프리셋이 적용됩니다.

기준 프로젝트는 30분 1080p, 음성 2트랙, 기본 배경, 커서, 자동 확대입니다. 콜드 시작은 재부팅 후 프로세스 미실행 상태, 파일 캐시는 조건을 명시합니다. 실제 측정값과 p50·p95·최댓값을 남깁니다.

| 항목 | 통과 기준 | 표본·조건 |
| --- | --- | --- |
| 콜드 앱 시작 | 조작 가능한 시작 화면까지 p95 ≤3초 | 각 장비 20회, 계정·네트워크 불필요 |
| 일반 UI 입력 | 상태 반응 p95 ≤100ms, 최댓값 ≤500ms | 장비별 재생 중 200회. 작업 전체 완료 시간과 구분 |
| 미리보기 탐색 | 마지막 탐색 요청부터 맞는 프레임 표시까지 p95 ≤300ms | 프록시 준비 후 장비별 무작위 100회 |
| 자동 확대 분석 | 5분 이벤트 분석 p95 ≤3초 | 20개 프로젝트. 프록시 생성은 별도 진행률 표시 |
| 영상 처리 | 60fps 인증 장비에서 프레임 합성·제출 p95 ≤16.7ms, 30fps는 ≤33.3ms | CPU·GPU·큐 대기 분리 측정, G04 프레임 손실도 동시에 통과 |
| 내보내기 속도 | 인증 장비·설정에서 영상 길이 이내 | 1·5·30분 프로젝트 각 3회. 나머지 지원 장비는 실측 속도 명시 |
| 메모리 상한 | 녹화 전체 프로세스 private bytes 최대 1GiB, 편집·출력 최대 2GiB | 기준 프로젝트, 정상 캐시 포함. GPU 메모리도 별도 보고 |
| 메모리 증가 | 녹화 시작 5분 대비 30분에서 private bytes 증가 ≤100MiB | 큐·캐시 상한 검사 병행. 종료 30초 후 녹화 전 +100MiB 이내 |

화질·속도를 자동 조정한다면 시작 전에 선택한 프로필과 실제 출력에 기록합니다. 기준을 맞추려고 녹화 중 사용자에게 알리지 않고 해상도·프레임률을 낮추지 않습니다. GPU 메모리 예산과 여유 디스크 계산은 지원 장비별로 문서화하고 장치 손실·공간 부족 대응을 G03에서 검증합니다.

## G06 — 사용성·접근성

제품에 처음 노출되는 목표 사용자 **10명**에게 동일한 60초 서비스 소개 과제를 부여합니다. 개발자·팀원은 표본에서 제외하고, 진행자가 버튼 위치를 알려주지 않습니다.

- 최소 9명이 도움 없이 녹화부터 MP4 저장까지 완료합니다.
- 첫 녹화 시작까지 중앙값 60초 이내, 최소 9명이 120초 이내에 시작합니다. 다운로드·설치 시간은 별도 보고합니다.
- 최소 8명이 첫 자동 결과에서 확대 구간 수정 2회 이내로 수용 가능한 영상을 완성합니다. 수용 기준은 중요한 버튼·조작이 보이고 설명 순서가 이해되는 것입니다.
- 작은 관찰 표본이라는 점을 보고서에 표시하며 시장 전체의 성공률로 홍보하지 않습니다.

키보드만으로 대상 선택·녹화 종료·미리보기·편집·내보내기·공유 삭제를 수행할 수 있어야 합니다. 타임라인 드래그에는 키보드·숫자 입력 대안을 제공합니다. Narrator가 필수 컨트롤의 이름·상태·값·오류를 읽고 포커스가 갇히지 않아야 합니다.

100~200% 디스플레이 배율과 지원하는 텍스트 확대 조합에서 중요한 버튼·설명이 잘리지 않아야 합니다. 밝은·어두운·고대비 테마에서 상태를 색만으로 표시하지 않습니다. Accessibility Insights의 필수 흐름 오류를 검토·해결하고 실제 키보드·Narrator 수동 테스트도 통과합니다. 도구 사용 근거: [Windows 접근성 테스트 도구](https://learn.microsoft.com/en-us/windows/win32/winauto/accessibility-testingtools), [앱 접근성 테스트](https://learn.microsoft.com/en-us/windows/apps/design/accessibility/accessibility-testing).

## G07 — 보안·개인정보

다음 항목은 첫 버전의 기능에 직접 연결된 필수 검증입니다.

- 녹화 전·종료 후에는 커서·입력 수집을 중단합니다. 명시적으로 선택한 대상과 장치만 수집합니다. 임의의 전체 키 입력 기록은 없습니다.
- 링크 공유 동작 전 영상·음성·이벤트가 서버로 전송되지 않음을 네트워크 캡처로 확인합니다. 진단 로그·오류 보고에도 해당 데이터와 창 제목을 기본 포함하지 않습니다.
- 로컬 녹화·편집·파일 저장이 오프라인·로그아웃 상태에서 완료됩니다. 인증 토큰·서명 키·저장소 비밀키를 프런트엔드나 평문 로그에 포함하지 않습니다.
- 프로젝트 파일·경로·미디어·IPC 입력을 검증합니다. 경로 이탈·외부 명령 실행·메모리·용량 고갈을 유발하는 악성 또는 손상 입력 샘플을 거부합니다.
- 공유 객체·삭제·수정·업로드 완료 요청의 소유권을 서버에서 검사합니다. 다른 사용자의 ID로 접근하는 모든 부정 테스트를 거부해야 합니다.
- 배포물의 의존성 목록·버전·라이선스 고지와 취약점 검사 결과를 남깁니다. 배포 경로에서 악용 가능한 Critical/High 취약점과 권한 경계 위반은 미해결 상태로 출시하지 않습니다. 오탐·비도달 판정에는 근거를 남깁니다.
- 업데이트는 인증된 출처와 서명을 검증하고 변조·신뢰되지 않는 패키지를 거부합니다. 서명 키는 릴리스 권한으로 제한합니다.

보안 검사 ‘0건’은 보안을 보장한다는 뜻이 아닙니다. 녹화 권한, 미디어 파싱, 프로젝트 경로, 공유 접근 제어, 업데이트 경로를 별도로 검토한 기록이 필요합니다.

## G09 — 공유의 완료와 운영 품질

‘링크를 가진 사람에게 공개’, 기본 7일 만료, 사용자 삭제를 첫 정식 공유 범위로 고정합니다. 공개 범위·만료 일시를 업로드 전에 표시하고, 서버 검증까지 완료된 영상에만 재생 가능한 링크를 제공합니다.

- 비공개 저장소를 사용합니다. 익명 저장소 목록·원본 객체 URL 접근, 다른 소유자의 수정·삭제를 거부합니다.
- 삭제·만료 후 새 재생 권한 발급은 즉시 중단합니다. 이미 발급된 미디어 접근 권한은 **최대 60초** 내 만료되도록 하고 CDN·캐시 우회 접근도 시험합니다. 만료 직전 발급 권한은 공유 만료 시각을 넘지 않게 합니다.
- 이미 다운로드했거나 클라이언트가 버퍼에 받은 데이터는 회수할 수 없음을 공유 안내에 명시합니다.
- 삭제 후 활성 저장소 원본·변환본·썸네일은 **24시간 이내** 제거합니다. 백업이 존재하면 보관 상한 30일과 삭제 기록 재적용을 구현해 복원 시 삭제 영상이 살아나지 않게 합니다.
- 업로드 중단·중복 요청·재시도·취소로 ready가 아닌 영상이 공개되거나 같은 작업의 과금·용량이 중복 집계되지 않아야 합니다.
- 사용자별 파일 크기·업로드·저장량·전송량 한도를 정하고 서버에서 강제합니다. 숫자와 초과 시 동작이 정해지지 않으면 출시 보류입니다.

서비스의 용량 목표 C는 출시 예상 동시 업로드·재생 수를 수치로 고정한 값입니다. C에서 60분 부하 테스트를 수행해 성공률 ≥99.5%, 제어 API p95 ≤500ms를 충족합니다. 2C에서 15분 시험 시 과부하를 제한·재시도 응답으로 처리하고 데이터 손상이나 다른 사용자 간 정보 노출이 없어야 합니다.

미디어 전체 전송 시간은 API 응답 시간에 포함하지 않습니다. 재생 시작은 고정 1080p 60초 샘플, 20Mbps·RTT 50ms 테스트 회선, 100회에서 p95 ≤3초로 검증합니다. 테스트 리전·캐시 상태·브라우저 버전을 기록합니다.

출시 전 동일 서버 후보로 7일 동안 5분 간격의 합성 업로드·재생·삭제 점검을 수행해 ≥99.5% 성공하고, 마지막 24시간은 미해결 실패가 없어야 합니다. 출시 후 30일 가용성 SLO도 ≥99.5%로 두되, 출시 전 7일 결과를 30일 실적이라고 표시하지 않습니다.

## G10 — 운영·배포 후 대응

담당자 실명, 대체 연락처, 서비스 장애 연락 수단, 오류 로그 위치, 사용자 지원 경로를 출시 기록에 남깁니다. 상시 대응이 불가능한 팀이라면 그 범위에 맞는 베타 운영을 유지하고 정식 공유 서비스를 약속하지 않습니다.

| 상황 | 동작과 기준 |
| --- | --- |
| 녹화 손실·무단 접근·서명 문제 신고 | P0·P1 분류, 해당 배포·기능 확장 중단, 원본 보존 안내. 최우선 조사 |
| 공유 합성 점검 연속 2회 실패 | 첫 실패 후 10분 이내 알림 발송, 알림 이후 30분 이내 담당자 확인 |
| 서버 장애 복구 | 통보 이후 4시간 이내 핵심 공유 경로 복구 목표. 정기 모의 복구에서 측정 |
| 데이터 복원 | 메타데이터 백업 복원 시 RPO ≤15분, RTO ≤4시간. 객체 대조와 삭제 기록 재적용 포함 |
| 비용·용량 | 정한 예산·용량 80%에서 알림, 100% 도달 시 신규 업로드 제한 정책 실행. 로컬 편집·저장은 유지 |
| 단계 배포 | 베타 → 제한된 정식 배포 → 전체 배포. 각 확대 전 24시간과 유효 녹화 100회 이상 관찰 |

작업을 실제로 실행한 모의훈련 기록이 필요합니다. 알림을 설정했다는 화면만으로는 통과하지 않습니다. 앱 다운로드 중단·업데이트 중단, 서버 정상 버전 복원, 삭제된 링크를 되살리지 않는 데이터 복원, 사용자 안내 초안 준비를 포함합니다.

초기 정식 배포 100회 관찰에서는 녹화·출력 실패가 2건 이상이거나, 규모와 관계없이 P0·P1이 1건 확인되면 배포 확대를 중단합니다. 원인 불명의 손실도 중단 사유입니다. 표본이 쌓이지 않으면 시간 경과만으로 전체 배포하지 않습니다.

## G11 — 결함 등급과 증거

| 등급 | 예시 | 정식 출시 판단 |
| --- | --- | --- |
| P0 | 무단 녹화·공유, 사용자 간 접근 제어 우회, 광범위 데이터 파괴, 업데이트 변조 실행 | 0건 필수. 발견 즉시 관련 배포·접근 경로 차단 |
| P1 | 지원 환경에서 원본 손실·프로젝트 손상·녹화 종료 불능·반복 충돌·핵심 저장 실패, 접근성으로 필수 작업 불가 | 미해결 0건 필수. 평균 성공률로 상쇄 불가 |
| P2 | 데이터 보존되고 우회 가능한 비핵심 기능 오류·제한적 UI 문제 | 필수 기준을 위반하지 않는 경우에만 영향·우회법·담당자·수정 목표 버전 기록 후 수용 가능 |
| P3 | 기능·가독성에 영향 없는 시각적 마감·문구 개선 | 목록화하고 후속 처리 가능 |

필수 기준 실패를 P2로 분류해 면제하지 않습니다. 원인 미확인 데이터 손실은 P1 이상으로 다룹니다. 현재 알려진 재현 절차를 회귀 테스트로 남기고 수정 후 확인합니다.

출시 증거에는 다음을 포함합니다.

- 소스 revision·앱/엔진 버전·의존성 잠금·빌드 설정·SDK·서버 revision.
- 실제 서명된 설치 파일 해시와 검증 결과, 이전 버전에서 이관한 프로젝트 샘플.
- 테스트 장비 목록·드라이버·프로필·시나리오·시드·표본 수·실패 수·원시 로그·판정 결과.
- 미디어 길이·동기화·좌표·프레임·성능 측정 보고서, 장애 복구·접근 제어·운영 훈련 증거.
- 사용자 검증 요약, 개인정보를 제외한 관찰 결과, 알려진 문제, 출시 책임자와 검토자의 판정.

기능 코드·엔진·의존성·빌드 설정이 바뀌면 기존 증거를 자동 승계하지 않습니다. 변경 영향에 따라 해당 게이트와 핵심 종단 테스트를 다시 수행합니다. 캡처·동기화·저장·인코딩 변경은 G02~G05의 영향을 받는 표본을 새 후보로 다시 확보합니다.
